# Payments (Sub-project 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire real money through the SP4 booking machine via Stripe Connect Express (test mode): deposit charges at accept, T+3 settlement with dunning and late fees, refund/forfeit on cancellation, musician payouts with an instant-cashout upsell.

**Architecture:** "Separate charges & transfers" — every charge lands in the platform Stripe account (escrow); transfers to musicians' Express accounts happen only at resolution. One `StripeLike` interface with a Firestore-backed `FakeStripe` for emulators (the geocoder DI pattern) and the real `stripe` SDK in production. Per-occurrence money truth lives in `bookings/{id}/payments/{gigId}` docs; an hourly `paymentsSweep` drives everything asynchronous (birth deposits, settlements, dunning, reconciliation).

**Tech Stack:** Firebase Functions v2 (onCall/onRequest/onSchedule), Firestore, `stripe` SDK (server), `@stripe/stripe-js` + `@stripe/react-stripe-js` (web), pnpm monorepo, vitest + emulator suite, Firestore rules tests.

**Spec:** `docs/superpowers/specs/2026-08-27-payments-design.md` — binding. SP4 contract: `docs/superpowers/sp4-rulings.md`.

## Non-negotiable invariants (repeat from spec — every task must respect these)

1. **No client-supplied amounts, ever.** Callables take ids (+ true-up quantities). Every cent is computed server-side from frozen `acceptedTerms` + the booking's `feePolicy` snapshot.
2. **Stripe calls NEVER run inside Firestore transactions.** Saga order: transactional validate/mark → Stripe call → transactional record. Crash windows are closed by Stripe idempotency keys (`{bookingId}:{gigId}:{purpose}` — a re-create with the same key returns the same object, never a double charge) + the hourly sweep's reconciliation.
3. **Money math:** integer cents; fees charged to the curator round **up** (`Math.ceil`); shares paid out round **down** (`Math.floor`); remainders to the platform. All new math lives in `packages/shared/src/money.ts`, unit-tested, no `Date.now()` in shared code.
4. **Secrets:** `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` via `defineSecret()` only (geocode.ts P5 pattern). Never a key in code, tests, or fixtures. Emulator = `FakeStripe` (selected when the secret env is absent), so the suite runs with no keys at all.
5. **Fee numbers (snapshot per booking as `feePolicy`, constants in shared):** curator +11% per charge, musician −2% on earnings transfers, instant cash-out −4% (min $1), late fee one-time 10% of outstanding split 7 (musician) / 3 (platform). Forfeits transfer **100%** of the deposit base (no commission); refunds always include the curator's fee share.
6. **Existing SP4 behavior must not drift** except where a task explicitly modifies it. `pnpm emu:test` (393 SP4 tests), `pnpm emu:rules` (66), shared 123 must stay green after every task, plus each task's new tests.

## Plan refinements vs. the spec (decided here, binding for implementers)

- `deposit.status` gains two transient states the spec's enum implied but didn't name: `"refund_pending"` / `"forfeit_pending"` (set transactionally when a cancellation commits; resolved to `"refunded"`/`"forfeited"` by the post-commit executor or the sweep's retry). Full machine: `unpaid → held → applied | refund_pending → refunded | forfeit_pending → forfeited`.
- Whole-run cancel money semantics (spec §5 made per-date rules explicit; run-level cancel needed one more line): a curator's **whole-run late cancel forfeits ONLY the next upcoming occurrence's deposit slice** (the one the strict-<72h window was measured against); every later future occurrence's deposit **refunds**. Musician whole-run cancel refunds all. This matches SP4, where the run-level `deposit` was always one occurrence's worth.
- Fee attribution is **per charge**: every charge's fee share = `ceil(chargeBase × 11 / 100)` computed on that charge's own base. The accept-batch deposit intent's amount is `Σ(slice_i + feeShare_i)`, and a per-occurrence refund refunds exactly `slice_i + feeShare_i` (partial refund by amount on the batch intent).
- Dunning cadence, concretely: first charge attempt at `settleAfter`. On failure: `past_due`, retries at +1d, +2d, +2d after each failure (≈ spec's day 1/3/5). After the 3rd retry fails (4 failed attempts total): `delinquent` — late fee added, curator blocked.
- Web env var for the publishable key: `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` (public, not a secret). The secret key must NEVER appear in `apps/web`.

```ts
import type { BudgetStructure } from "./types.js";
import { computeExpectedTotalCents } from "./validation.js";

// All SP5 money math. Pure, integer-cents, no Date.now() (shared-code rule).
// Rounding law (spec §1): fees charged to the curator round UP, shares paid
// out round DOWN, remainders go to the platform.

const MAX_CENTS = 2 ** 45; // far above MAX_OFFER_AMOUNT_CENTS-derived totals; guards ceil/floor precision

function assertCents(v: number, label: string): void {
  if (typeof v !== "number" || !Number.isInteger(v) || v < 0 || v > MAX_CENTS) {
    throw new Error(`${label} must be an integer number of cents in [0, 2^45].`);
  }
}

// ceil(base * pct / 100) — the curator-side fee share carried by ONE charge.
export function computeFeeShareCents(baseCents: number, feePct: number): number {
  assertCents(baseCents, "baseCents");
  return Math.ceil(baseCents * feePct / 100);
}

// floor(base * (100 - pct) / 100) — the musician's earnings on a base amount.
export function computeEarningsCents(baseCents: number, musicianFeePct: number): number {
  assertCents(baseCents, "baseCents");
  return Math.floor(baseCents * (100 - musicianFeePct) / 100);
}

export function computeLateFeeSplit(
  outstandingCents: number, lateFeePct: number, lateFeeMusicianPct: number,
): { lateFeeCents: number; musicianCents: number; platformCents: number } {
  assertCents(outstandingCents, "outstandingCents");
  const lateFeeCents = Math.ceil(outstandingCents * lateFeePct / 100);
  const musicianCents = Math.floor(lateFeeCents * lateFeeMusicianPct / lateFeePct);
  return { lateFeeCents, musicianCents, platformCents: lateFeeCents - musicianCents };
}

export function computeInstantFeeCents(
  amountCents: number, instantFeePct: number, minCents: number,
): number {
  assertCents(amountCents, "amountCents");
  return Math.max(minCents, Math.ceil(amountCents * instantFeePct / 100));
}

// The occurrence's FINAL settlement base: frozen amountCents applied to the
// occurrence's own quantities plus increase-only true-ups. Negative/invalid
// true-ups clamp to 0 (defensive — the callable validates before writing).
export function computeSettlementBaseCents(
  structure: BudgetStructure,
  amountCents: number,
  opts: { durationMinutes: number; extraMinutes: number; songCount: number | null; extraSongs: number },
): number {
  assertCents(amountCents, "amountCents");
  const extraMinutes = Number.isInteger(opts.extraMinutes) && opts.extraMinutes > 0 ? opts.extraMinutes : 0;
  const extraSongs = Number.isInteger(opts.extraSongs) && opts.extraSongs > 0 ? opts.extraSongs : 0;
  return computeExpectedTotalCents(structure, amountCents, {
    durationMinutes: opts.durationMinutes + extraMinutes,
    songCount: (opts.songCount ?? 0) + extraSongs,
  });
}
```

```ts
// ---------- FakeStripe (emulator/tests) ----------
// State lives in Firestore so the functions process and the test process see
// the same world:
//   stripeFake/config           { declineCharges?: boolean }   (test knob, admin-SDK-written)
//   stripeFake/idem/keys/{key}  { result }                     (idempotency replay)
//   stripeFake/objects/{id}     { kind, ... }                  (created objects, incl. account state)
// Counters use doc ids derived from the idempotency key (deterministic), or a
// random doc id where no key applies.
export class FakeStripe implements StripeLike {
  private db = getFirestore();

  private async idem<T>(key: string, make: () => Promise<T>): Promise<T> {
    const ref = this.db.doc(`stripeFake/idem/keys/${encodeURIComponent(key)}`);
    const snap = await ref.get();
    if (snap.exists) return snap.data()!.result as T;
    const result = await make();
    await ref.set({ result });
    return result;
  }

  private async shouldDecline(): Promise<boolean> {
    const cfg = await this.db.doc("stripeFake/config").get();
    return cfg.data()?.declineCharges === true;
  }

  private newId(prefix: string): string {
```

```ts
import { getFirestore } from "firebase-admin/firestore";
import type { LedgerEntry, LedgerKind, PaymentDoc, PaymentSummary } from "@gatekeep/shared";

// Append-only audit row for every money event. Best-effort at call sites that
// run post-commit (a failed ledger write must never fail a committed money
// move — callers wrap in try/catch); the sweep's reconciliation re-derives
// nothing from the ledger, so a lost row is an audit gap, not a money bug.
export async function writeLedger(entry: Omit<LedgerEntry, "at"> & { at?: number }): Promise<void> {
  const db = getFirestore();
  const full: LedgerEntry = { ...entry, at: entry.at ?? Date.now() } as LedgerEntry;
  await db.collection("ledger").add(full);
}

// Recomputes bookings/{id}.paymentSummary from the payments subcollection.
// Self-healing aggregate (recompute-from-truth, like recomputeReliability) —
// call after any payment-doc transition. `state` is the max-severity of any
// occurrence: delinquent > past_due > current. Delinquency is decided by the
// sweep (Task 10) via private/stripe.delinquent; here past_due alone is
// derived from settlement statuses.
export async function recomputePaymentSummary(bookingId: string): Promise<void> {
  const db = getFirestore();
  const snap = await db.collection(`bookings/${bookingId}/payments`).get();
  let heldCents = 0, paidCents = 0, transferredCents = 0;
  let anyPastDue = false, anyDelinquent = false;
  for (const doc of snap.docs) {
    const p = doc.data() as PaymentDoc;
    if (p.deposit.status === "held" || p.deposit.status === "applied") heldCents += p.deposit.sliceCents;
    if (p.deposit.status === "held" || p.deposit.status === "applied") paidCents += p.deposit.sliceCents + p.deposit.feeShareCents;
    if (p.settlement.status === "paid") paidCents += (p.settlement.computedCents ?? 0) + (p.settlement.feeShareCents ?? 0) + (p.settlement.lateFeeCents ?? 0);
    if (p.settlement.status === "past_due") {
      anyPastDue = true;
      if (p.settlement.lateFeeCents != null) anyDelinquent = true; // late fee set <=> delinquency reached
    }
    if (p.transfer.status === "transferred") transferredCents += p.transfer.amountCents ?? 0;
  }
  const summary: PaymentSummary = {
    state: anyDelinquent ? "delinquent" : anyPastDue ? "past_due" : "current",
    heldCents, paidCents, transferredCents,
  };
  await db.doc(`bookings/${bookingId}`).update({ paymentSummary: summary, updatedAt: Date.now() });
}
```

```ts
import { onRequest } from "firebase-functions/v2/https";
import { getFirestore } from "firebase-admin/firestore";
import { getStripe, stripeSecretKey, stripeWebhookSecret } from "./stripeClient.js";

// The codebase's ONLY non-callable HTTPS entry point. Contract:
//  - raw-body signature verification (RealStripe.constructWebhookEvent throws
//    on a bad signature; FakeStripe accepts anything — emulator only);
//  - stripeEvents/{eventId} transactional create-if-absent = exactly-once
//    processing per event id (replays and concurrent deliveries no-op);
//  - handlers are dispatched by type and must individually tolerate
//    out-of-order delivery (each re-reads current state, never assumes).
// Handlers are REGISTERED here but implemented across tasks:
//  - account.updated        -> Task 4 (cached gate flags)
//  - payment_intent.succeeded -> Task 10 (payPastDue completion)
//  - payout.paid/payout.failed -> Task 13
//  - transfer.reversed      -> Task 12 (ledger only)
// Unknown/unhandled types: record the event doc, 200 OK (Stripe requires 2xx
// or it retries forever).
export type WebhookHandler = (object: Record<string, unknown>, eventId: string) => Promise<void>;
export const webhookHandlers: Record<string, WebhookHandler> = {};

export const stripeWebhook = onRequest(
  { region: "us-central1", secrets: [stripeSecretKey, stripeWebhookSecret] },
  async (req, res) => {
    if (req.method !== "POST") { res.status(405).end(); return; }
    const stripe = getStripe();
    let event: { id: string; type: string; data: { object: Record<string, unknown> } };
    try {
      event = stripe.constructWebhookEvent(req.rawBody.toString("utf8"), req.headers["stripe-signature"] as string ?? "");
    } catch {
      res.status(400).send("bad signature");
      return;
    }
    if (typeof event?.id !== "string" || typeof event?.type !== "string") {
      res.status(400).send("bad event");
      return;
    }

    const db = getFirestore();
    const eventRef = db.doc(`stripeEvents/${event.id}`);
    // Exactly-once claim: create-if-absent inside a transaction. A replay
    // (doc already exists) returns 200 without re-processing.
    const fresh = await db.runTransaction(async (tx) => {
      const snap = await tx.get(eventRef);
      if (snap.exists) return false;
      tx.set(eventRef, { type: event.type, receivedAt: Date.now(), processed: false });
      return true;
    });
    if (!fresh) { res.status(200).send("duplicate"); return; }

    const handler = webhookHandlers[event.type];
    if (handler) {
      try {
        await handler(event.data.object, event.id);
        await eventRef.update({ processed: true, processedAt: Date.now() });
      } catch (e) {
        console.error(`stripeWebhook: handler for ${event.type} failed (event ${event.id})`, e);
        // Delete the claim so Stripe's retry re-processes — a handler failure
        // must not be swallowed by the idempotency guard.
        await eventRef.delete().catch(() => {});
        res.status(500).send("handler failed");
        return;
      }
    } else {
      await eventRef.update({ processed: true, processedAt: Date.now() });
    }
    res.status(200).send("ok");
  });
```

```ts
// Resolves one payment doc's *_pending deposit to its terminal state via
// Stripe. Idempotent end-to-end: keys are per-(booking,gig,purpose); a re-run
// (executor + sweep both firing) converges on the same Stripe objects and the
// doc CAS (status still *_pending) makes the second writer a no-op.
export async function resolveDepositPending(bookingId: string, gigId: string): Promise<void> {
  const db = getFirestore();
  const ref = db.doc(`bookings/${bookingId}/payments/${gigId}`);
  const snap = await ref.get();
  const p = snap.data() as PaymentDoc | undefined;
  if (!p) return;
  const now = Date.now();

  if (p.deposit.status === "refund_pending") {
    if (!p.deposit.intentId) { // never charged (unpaid at cancel time) — nothing to refund
      await ref.update({ "deposit.status": "refunded", "deposit.resolvedAt": now, updatedAt: now });
      return;
    }
    const amount = p.deposit.sliceCents + p.deposit.feeShareCents; // fee ALWAYS refunds (spec §1)
    const r = await getStripe().refund({
      intentId: p.deposit.intentId, amountCents: amount,
      idempotencyKey: `${bookingId}:${gigId}:refund`, meta: { bookingId, gigId, purpose: "deposit_refund" },
    });
    await ref.update({ "deposit.status": "refunded", "deposit.resolvedAt": now, updatedAt: now });
    await writeLedger({ kind: "refund", amountCents: amount, bookingId, gigId,
      profileId: p.curatorProfileId, stripeId: r.id, detail: "deposit refund (incl. fee share)" }).catch(() => {});
  } else if (p.deposit.status === "forfeit_pending") {
    // 100% of the deposit BASE to the musician (no commission on forfeits);
    // platform keeps the fee share by simply not refunding it.
    const musicianStripe = await getStripeProfileDoc(p.musicianProfileId);
    if (!musicianStripe?.accountId) {
      console.error(`resolveDepositPending: no account for forfeit ${bookingId}/${gigId} — left pending for sweep`);
      return; // unreachable in normal flow (accept gated on payout-ready); sweep retries
    }
    const t = await getStripe().transferToAccount({
      accountId: musicianStripe.accountId, amountCents: p.deposit.sliceCents,
      idempotencyKey: `${bookingId}:${gigId}:forfeit`, meta: { bookingId, gigId, purpose: "forfeit" },
    });
    await ref.update({
      "deposit.status": "forfeited", "deposit.resolvedAt": now, "deposit.forfeitTransferId": t.id, updatedAt: now,
    });
    await writeLedger({ kind: "forfeit_transfer", amountCents: p.deposit.sliceCents, bookingId, gigId,
      profileId: p.musicianProfileId, stripeId: t.id, detail: "deposit forfeited to musician (100%)" }).catch(() => {});
  }
  await recomputePaymentSummary(bookingId).catch(() => {});
}

// Marks every FUTURE unresolved payment doc of a booking *_pending inside the
// caller's transaction. `forfeitGigId` names the ONE doc that forfeits (run-
// level curator late cancel); null = refund everything. Returns the touched
// gigIds so the caller can run the executor post-commit.
export function markDepositsPendingInTx(
  tx: FirebaseFirestore.Transaction, db: FirebaseFirestore.Firestore,
  bookingId: string, paymentDocs: FirebaseFirestore.QueryDocumentSnapshot[],
  forfeitGigId: string | null, now: number,
): string[] {
  const touched: string[] = [];
  for (const doc of paymentDocs) {
    const p = doc.data() as PaymentDoc;
    if (p.deposit.status !== "held" && p.deposit.status !== "unpaid") continue; // settled/resolved docs untouched
    const next = p.gigId === forfeitGigId ? "forfeit_pending" : "refund_pending";
    tx.update(doc.ref, { "deposit.status": next, updatedAt: now });
    // A cancelled occurrence never settles.
    if (p.settlement.status === "not_due" || p.settlement.status === "pending") {
      tx.update(doc.ref, { "settlement.status": "waived" });
    }
    touched.push(p.gigId);
  }
  return touched;
}
```

```ts
    if (booking.structure === "perSong" && extraMinutes > 0) throw new HttpsError("invalid-argument", "This booking bills per song — report extra songs.");

      const ref = db.doc(`bookings/${bookingId}/payments/${gigId}`);
      const snap = await tx.get(ref);
      const p = snap.data() as PaymentDoc | undefined;
      if (!p) throw new HttpsError("not-found", "No payment record for that date.");
      if (p.settlement.status !== "pending") {
        throw new HttpsError("failed-precondition", "Actuals can only be reported during the settlement window.");
      }
      const prev = p.settlement.trueUp;
      if (prev && (extraMinutes < prev.extraMinutes || extraSongs < prev.extraSongs)) {
        throw new HttpsError("failed-precondition", "Reported actuals can only increase.");
      }
      tx.update(ref, { "settlement.trueUp": { extraMinutes, extraSongs, reportedAt: now }, updatedAt: now });
    });
    return { ok: true };
  });
```

```ts
// frozen terms + true-up + the gig's own duration, charge `final - deposit
// slice` + fee (skipping a zero charge), then transfer earnings. CAS: only
// acts when settlement.status is "pending"/"past_due". Returns what happened
// so the sweep can count.
export async function chargeSettlement(bookingId: string, gigId: string, now: number):
  Promise<"charged" | "declined" | "delinquent" | "skipped"> {
  const db = getFirestore();
  const ref = db.doc(`bookings/${bookingId}/payments/${gigId}`);
  const [pSnap, bookingSnap, gigSnap] = await Promise.all([
    ref.get(), db.doc(`bookings/${bookingId}`).get(), db.doc(`gigs/${gigId}`).get(),

  if (p.settlement.status !== "pending" && p.settlement.status !== "past_due") return "skipped";

  if (gig.bookingId !== bookingId || gig.status !== "filled") {
    await ref.update({ "settlement.status": "waived", updatedAt: now });
    if (p.deposit.status === "held") {
      await ref.update({ "deposit.status": "refund_pending" });
      await resolveDepositPending(bookingId, gigId);
    }
    return "skipped";
  }

  const finalBase = computeSettlementBaseCents(booking.structure, booking.acceptedTerms.amountCents, {
    durationMinutes: gig.durationMinutes,
    extraMinutes: p.settlement.trueUp?.extraMinutes ?? 0,
    songCount: booking.acceptedTerms.expectedQuantity,
    extraSongs: p.settlement.trueUp?.extraSongs ?? 0,
  });

  // true-ups; refund the difference instead of charging if it ever happens.

  const feeShare = due > 0 ? computeFeeShareCents(due, booking.feePolicy.curatorFeePct) : 0;
  const lateFee = p.settlement.lateFeeCents ?? 0; // present once delinquent (Task 11)

  let intentId = p.settlement.intentId;

    const curatorStripe = await getStripeProfileDoc(p.curatorProfileId);
    if (!curatorStripe?.customerId) return "skipped";

      const r = await getStripe().chargeOffSession({
        customerId: curatorStripe.customerId, amountCents: due + feeShare + lateFee,
        // attempts in the key: a RETRY after a decline is a NEW Stripe
        // request (the declined one is terminal under its own key).
        idempotencyKey: `${bookingId}:${gigId}:settle:${p.settlement.attempts}`,
        meta: { bookingId, gigId, purpose: "settlement" },

      intentId = r.id;

      if (e instanceof StripeCardDeclinedError) return await recordSettlementFailure(bookingId, gigId, p, booking, now);
      throw e;
    }
  } else if (due < 0) {
    await getStripe().refund({
      intentId: p.deposit.intentId!, amountCents: -due,
      idempotencyKey: `${bookingId}:${gigId}:settle-down`, meta: { bookingId, gigId, purpose: "below_deposit_refund" },
    });
  }

  // Earnings: 98% of finalBase + the musician's late-fee share (Task 11).
  const musicianStripe = await getStripeProfileDoc(p.musicianProfileId);
  const earnings = computeEarningsCents(finalBase, booking.feePolicy.musicianFeePct)
    + (p.settlement.lateFeeMusicianCents ?? 0);
  const t = await getStripe().transferToAccount({
    accountId: musicianStripe!.accountId!, amountCents: earnings,
    idempotencyKey: `${bookingId}:${gigId}:earn`, meta: { bookingId, gigId, purpose: "earnings" },

    "settlement.status": "paid", "settlement.computedCents": Math.max(0, due), "settlement.feeShareCents": feeShare,
    "settlement.intentId": intentId ?? null, "settlement.nextRetryAt": null,
    "deposit.status": "applied", "deposit.resolvedAt": now,
    "transfer.status": "transferred", "transfer.id": t.id, "transfer.amountCents": earnings, "transfer.transferredAt": now,
    updatedAt: now,
  });
  await writeLedger({ kind: "settlement_charged", amountCents: due + feeShare + lateFee, bookingId, gigId,
    profileId: p.curatorProfileId, stripeId: intentId, detail: "settlement charge" }).catch(() => {});

    profileId: p.musicianProfileId, stripeId: t.id, detail: "earnings transfer (98% + late-fee share)" }).catch(() => {});

  await clearDelinquencyIfSettled(p.curatorProfileId, now).catch(() => {});   // Task 11
  try {
    await notifyProfileMembers(p.musicianProfileId, { kind: "booking", refId: bookingId,
      title: "You've been paid", body: "A settlement landed in your balance — cash out from your Earnings page." });
  } catch { /* best-effort */ }
  return "charged";
}
```

## As-built contract changes from Task 2's review (BINDING on later tasks)

Task 2's quality review hardened the Stripe layer; these override the earlier task snippets where they conflict:

1. **`chargeOffSession` THROWS on every non-success** (`StripeCardDeclinedError` with `code`, or `StripePaymentPendingError` for `processing` — transient: retry later with the SAME key, never a new attempt) and returns `{ id, chargeId }`. No `status` field exists — callers never branch on it.
2. **Declines are CACHED under their idempotency key** (fake and real Stripe both) — so every retry-after-decline needs an attempt-scoped key:
   - Task 6 accept saga: transaction A persists an incrementing `depositChargeAttempt` counter on the booking; charge key is `{bookingId}:accept:deposit:{attempt}`. Crash-reconciliation (Task 9 step 1) reuses the PERSISTED attempt value — same attempt, same key; a NEW accept try after a decline re-stages with attempt+1.
   - Task 9 birth deposits: key `{bookingId}:{gigId}:deposit:{depositAttempts}` (the persisted counter; increments only on decline).
   - Task 12 restore re-run: bump `settlement.attempts` when re-opening a clawed-back settlement so its `settle:`/`earn:` keys differ from the consumed ones (otherwise both charge and transfer silently replay and no money moves).
3. **Transfers backed by a fresh charge must pass `sourceChargeId`** (Task 10's earnings transfer passes the settlement charge's `chargeId`; Task 8's forfeit transfer passes the deposit charge's `chargeId` when available) — avoids `balance_insufficient` on pending balances in real mode.
4. **Task 13 instant payouts** check `getInstantAvailableBalanceCents` (not the standard bucket); `setDefaultPaymentMethod` exists — Task 4's refreshPaymentMethod sets the newest card as the customer default.
5. **Task 9 reconciliation guard**: real Stripe idempotency keys expire after 24h — a booking stuck `depositChargePending` for >24h is NOT blindly recharged; the sweep logs an error metric for admin attention instead.
6. FakeStripe decline knob is scopable: `stripeFake/config.declineCustomerIds: string[]` alongside the global flag — tests should scope declines to their own customer to avoid cross-file interference.
